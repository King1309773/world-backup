# World Backup 1.0.0 使用说明

适用于 Minecraft 1.12.2、Forge 14.23.5.2860 和 Java 8，仅支持单人世界。

## 安装与首次使用

1. 关闭游戏，将 `worldbackup-1.0.0.jar` 放入目标游戏实例的 `mods` 文件夹。
2. 确保该实例只有一份 World Backup JAR，再启动游戏。
3. 在模组列表中找到 World Backup，进入配置界面调整设置。配置文件为游戏目录下的 `config/worldbackup.cfg`。
4. 进入单人世界，默认在世界就绪 10 秒后备份一次；完成后聊天栏显示成功及耗时，失败时显示耗时与原因。

发布包中的 `SHA256SUMS.txt` 可用于核对解压后各文件是否完整。在 PowerShell 中执行 `Get-FileHash -Algorithm SHA256 .\worldbackup-1.0.0.jar`，将结果与校验文件中的对应行比较。

## 配置与默认值

| 配置 | 默认值 | 用途 |
| --- | --- | --- |
| `enabled` | `true` | 备份总开关 |
| `scheduledEnabled` | `true` | 定时备份开关 |
| `worldLoadEnabled` | `true` | 每次进入世界就绪 10 秒后备份一次 |
| `exitEnabled` | `true` | 退出世界时备份 |
| `mode` | `INCREMENTAL` | 智能增量；也可选 `FULL` 全量或 `OVERWRITE` 覆写 |
| `intervalMinutes` | `20` | 定时备份间隔，单位为分钟，最小为 1 |
| `maxVersions` | `10` | 最多可见恢复点数量，最小为 1 |
| `incrementsPerBase` | `5` | 一个全量基线后最多连续创建的增量数 |
| `backupPath` | `backups` | 备份根目录，支持相对游戏目录的路径或绝对路径 |

进入世界备份与定时备份独立。协调器忙碌时，进入世界备份会静默等待并重试，直到请求被接受；同一轮进入只接受一次。

手动备份按键默认未绑定。请在“选项 → 控制 → 世界备份”中绑定“创建手动备份”。

## 备份与恢复

备份默认保存在 `backups/<世界文件夹>/`，包含 `index.json` 和全量、增量或覆写 ZIP。增量包依赖基线与前序增量，请一起保留索引和归档，避免手动删除链中某个文件。

在单人世界选择界面选择世界，点击右上角“备份管理”，可查看版本、触发来源、时间、大小和耗时，并恢复或删除版本。恢复必须在世界未加载时进行；模组先重建并校验目标版本，再替换世界。恢复期间请等待进度界面完成。

原世界会保留为 `restore-safety/<世界文件夹>-时间戳[-序号]/` 安全副本。可在管理器“安全副本”页查看和删除；删除是永久操作。

可见版本达到上限后，仍被增量链依赖的旧归档会作为隐藏依赖保留，因此磁盘文件数量可能超过 `maxVersions`。

## 空间与使用边界

- 一致性快照暂时需要接近一份世界大小的额外空间；复制阶段世界会暂停，随后压缩与校验在后台继续。
- `.mca` 按整文件备份，不做区块级差分。大小与修改时间都不变时会复用历史 SHA-256；外部工具同时保留二者的内容改写可能无法识别。
- 修改 `backupPath` 不会搬迁已有备份。它不能与活动世界目录或内部 `.worldbackup-staging` 目录互相包含。
- 索引大小上限为 64 MiB。隐藏依赖、恢复安全副本也会占用磁盘空间。
- 极端恢复失败时，界面与日志会显示已经验证的抢救目录；先关闭游戏并完整复制相关目录，再人工处理。不要直接覆盖或清空它们。

完整故障恢复与实现限制见源码仓库的 `README.md`。发布包仅含模组与文档，不包含 Minecraft、Forge、Java、用户存档或游戏配置。
