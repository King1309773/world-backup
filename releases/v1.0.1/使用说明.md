# World Backup 1.0.1 使用说明

适用于 Minecraft 1.12.2、Forge 14.23.5.2860、Java 8，仅支持单人世界。

## 安装或升级

1. 关闭游戏，备份重要存档。
2. 移出 `mods` 中的旧版 World Backup JAR，放入 `worldbackup-1.0.1.jar`，确保只加载一份。
3. 启动游戏；现有配置与备份格式不变，无需删除配置或转换备份。
4. 在模组配置界面调整设置，或关闭游戏后编辑 `config/worldbackup.cfg`。

发布包的 `SHA256SUMS.txt` 记录各文件 SHA-256。在 PowerShell 中运行 `Get-FileHash -Algorithm SHA256 .\worldbackup-1.0.1.jar`，与校验文件比较。校验用于检查完整性，不是数字签名。

## 配置与默认值

| 配置 | 默认值 | 用途 |
| --- | --- | --- |
| `enabled` | `true` | 备份总开关 |
| `scheduledEnabled` | `true` | 定时备份开关 |
| `worldLoadEnabled` | `true` | 每次进入世界就绪 10 秒后备份一次 |
| `exitEnabled` | `true` | 退出世界时备份 |
| `mode` | `INCREMENTAL` | 智能增量；也支持 `FULL` 全量与 `OVERWRITE` 覆写 |
| `intervalMinutes` | `20` | 定时间隔，分钟，最小为 1 |
| `maxVersions` | `10` | 最多可见恢复点数量，最小为 1 |
| `incrementsPerBase` | `5` | 每个全量基线后最多连续创建的增量数 |
| `backupPath` | `backups` | 相对游戏目录或绝对备份路径 |

进入世界备份与定时备份独立；协调器忙碌时，进入世界备份会静默等待并重试。手动备份按键默认未绑定，在“选项 → 控制 → 世界备份”中绑定。备份完成或失败后，聊天栏显示结果及耗时。

## 管理与恢复

默认备份目录是 `backups/<世界文件夹>/`。请完整保留 `index.json` 与 ZIP 归档；增量依赖基线和前序增量，不要手动删除链中单个文件。必要的隐藏依赖不计入可见恢复点上限，因此磁盘归档数可能超过 `maxVersions`。

在单人世界选择界面选中世界，点击右上角“备份管理”，可浏览、校验、恢复和删除版本。恢复要求世界未加载；模组先重建并校验目标版本，再替换世界。原世界保存在 `restore-safety/<世界文件夹>-时间戳[-序号]/`，可在“安全副本”页管理；删除安全副本是永久操作。

## 空间、性能与限制

- 一致性快照需要接近一份世界大小的临时空间；复制期间世界仍会暂停，随后归档在后台继续。1.0.1 并非无停顿备份。
- `.mca` 按整文件处理，不做区块差分。文件大小和修改时间均未变时会复用历史 SHA-256；外部工具同时保留二者的内容改写可能无法识别。
- 修改 `backupPath` 不搬迁旧备份；路径不能与活动世界或内部 `.worldbackup-staging` 互相包含。索引上限为 64 MiB。
- 隐藏依赖和恢复安全副本也占磁盘空间。极端恢复失败时，先关闭游戏并完整复制日志所示抢救目录，不要清空或直接覆盖。
- 日志新增保存、快照扫描/复制、恢复保存、清理和归档阶段耗时。模拟基准不代表实际游戏完整停顿或帧率改善。

完整限制与故障恢复见 [源码 README](https://github.com/King1309773/world-backup/blob/v1.0.1/README.md)。发布包不包含 Minecraft、Forge、Java、用户存档或游戏配置。
